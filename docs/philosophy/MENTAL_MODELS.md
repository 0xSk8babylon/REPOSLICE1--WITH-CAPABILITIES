# Mental Models

## Living House Model

The core domain is the house over time, not a one-time quote. The system should accumulate facts, design options, and infrastructure consequences as the property evolves.

## Guided Infrastructure Literacy

The platform should help users understand how panels, loads, products, siting, and pathways interact. It should teach enough to improve decisions without pretending to replace engineering practice.

## Conversational but Grounded AI

AI can make the system easier to use, but only when it is anchored to current structured state. Narrative convenience must not replace persisted facts.

## Trust Layers

Not all information deserves the same confidence. The product should distinguish demo, user-entered, imported, verified, derived, and placeholder information clearly.

## Infrastructure Dependency Mapping

Products do not exist in isolation. Every design choice affects routing, panel strategy, siting, backup behavior, expansion cost, and future upgrade paths.

## Expansion Penalty

Deferring infrastructure decisions can create future retrofit cost, site disruption, and architectural lock-in. The product should make those penalties legible.

## Design Maturity

A design moves through planning maturity stages. That maturity is useful for collaboration, but it is not the same as code compliance, field validation, or engineering approval.

## Scenario Comparison As Decision Support

Scenario comparison should help users inspect tradeoffs, not just rank options. The output should show confidence, assumptions, and limitations alongside comparison signals.

## Site Verification Boundary

Some planning facts remain uncertain until field validation. The system should preserve a clear boundary between planning logic and site-confirmed truth.

## Product Ecosystems As Infrastructure Philosophies

Products are not just SKUs. They often imply architecture, upgrade patterns, compatibility posture, and operational philosophy that affect future decisions.

## Takeoffs As Derived Planning Views

Takeoffs are currently downstream views derived from planning state. They should not be treated as authoritative procurement records until versioned snapshot rules exist.

## Homeowner Mode Vs Contractor Mode

The same system should support novice understanding and deeper professional workflows. Simplicity for one audience must not destroy structure needed by the other.
