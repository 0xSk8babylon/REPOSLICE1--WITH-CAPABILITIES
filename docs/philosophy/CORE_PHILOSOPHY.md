# Core Philosophy

## Purpose

This doctrine layer exists to keep future implementation work strategically coherent. It is a memory aid for product intent, architecture discipline, and scope control.

## Core Principles

1. The house is a living energy system.
2. As the house grows, homeowner understanding should grow with it.
3. The platform organizes complexity rather than hiding it.
4. AI explains; structured data decides.
5. Trust visibility is more important than false certainty.
6. Planning guidance is not permit-grade engineering.
7. Products enable pathways, and pathways shape future infrastructure options.
8. The app should teach through interaction.
9. The system should model tradeoffs, not just equipment.
10. Preserve extensibility over short-term feature hacks.

## Strategic Implications

- Persist house context, design context, pathways, and product choices over time.
- Keep rules, calculations, explanations, and structured facts as separate layers.
- Prefer additive systems that preserve continuity over one-off feature shortcuts.
- Make partial knowledge visible instead of manufacturing confidence.
- Treat comparison, planning, and learning as first-class product behavior.

## Doctrine For Future Sessions

- If a proposed change hides uncertainty, challenge it.
- If a proposed feature bypasses structured state, challenge it.
- If a local optimization weakens extensibility or continuity, reject it unless explicitly directed otherwise.
- If a UI or API change makes the product look more authoritative than it is, correct that direction.
