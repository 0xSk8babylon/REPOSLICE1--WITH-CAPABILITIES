# Project Skill Recommendations

## Created Skills

- `doctrine-formalization`: doctrine, philosophy, ADR, and terminology changes
- `continuity-governance`: restore flow, discovery files, handoffs, and project memory
- `topology-intelligence`: current/proposed topology, scenario revisions, and lifecycle intelligence
- `orchestration-readiness`: DER, utility, contractor, AI-safe, and operational-control planning
- `canonical-authority-discipline`: authority layer separation and terminology normalization
- `provenance-lineage`: source lineage, trust states, derived outputs, and AI grounding
- `roadmap-continuity`: sequencing, active tasks, deferred architecture, and future phases

## Trigger Guidance

Future agents should load project skills before implementation when the task touches:

- architecture doctrine
- continuity restoration
- provenance or trust posture
- topology lifecycle
- roadmap sequencing
- future orchestration
- authority boundaries between canonical, derived, advisory, and operational knowledge

## Maintenance Rule

Keep project skills concise. They should route agents to canonical docs and checks, not duplicate the full doctrine.
